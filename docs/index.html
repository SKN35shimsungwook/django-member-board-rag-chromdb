따라 하기 · 가이드 PDF 1~11단계

9단계로 본 실제 작업

어디서 했는지도 적었습니다. "내 PC"는 Windows PowerShell, "서버"는 SSH로 접속한 EC2 리눅스, "AWS 콘솔"은 웹 화면입니다.

  1. 코드를 GitHub에 올리기

    회원·게시판 RAG 프로젝트만 Public 저장소에 올렸습니다. Public이라 서버가 비밀번호 없이 받아 갈 수 있습니다.

    본사 창고에 매장에서 쓸 물건을 넣어 두는 단계

    # 내 PC
git push origin main

    주의: .env(API 키·비밀번호)는 절대 올리지 않습니다. .gitignore로 빠져 있습니다.

  2. AWS에서 컴퓨터 빌리기 (EC2)

    Ubuntu 24.04, t3.small, 디스크 20GB로 만들었습니다. 접속용 열쇠(키 페어)와 문 설정(보안그룹)도 같이 정합니다.

    상가를 임대하고 열쇠를 받는 단계

    # AWS CloudShell (두 번째 배포 때는 콘솔 클릭 대신 명령으로)
aws ec2 run-instances --instance-type t3.small --key-name django-rag-ec2 ...

    t2.micro(1GB)는 MySQL과 ChromaDB를 같이 돌리기에 메모리가 모자라서 가이드도 t3.small 이상을 권합니다.

  3. 주소 고정하기 (탄력적 IP)

    서버에 13.209.205.180을 붙였습니다. 이게 없으면 서버를 재시작할 때마다 주소가 바뀝니다.

    도로명 주소를 받는 단계

  4. 서버에 들어가서 Docker 깔기

    SSH로 서버에 접속해 Docker를 설치하고, 메모리가 모자랄 때를 대비해 스왑 2GB를 만들었습니다.

    빈 상가에 들어가 전기·수도를 연결하는 단계

    # 내 PC → 서버 접속
ssh -i ~/.ssh/django-rag-ec2 ubuntu@13.209.205.180
# 서버
curl -fsSL https://get.docker.com | sudo sh

  5. 코드 받고 비밀 설정 파일 만들기

    GitHub에서 코드를 받고, GitHub에 없는 .env(DB 비밀번호, OpenAI 키, 허용 주소)를 서버에만 따로 만들었습니다.

    창고에서 물건을 받고, 금고 비밀번호는 직접 들고 가는 단계

    # 서버
git clone https://github.com/SKN35shimsungwook/django-member-board-rag-chromdb.git ~/app
# .env 안의 항목 이름 (값은 비밀)
MYSQL_PASSWORD  DJANGO_SECRET_KEY  DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=13.209.205.180  OPENAI_API_KEY

  6. 한 번에 켜기 (Docker Compose)

    운영용 설정 파일 하나로 nginx, Django, MySQL 세 상자를 만들고 켭니다. 처음엔 이미지를 만드느라 몇 분 걸립니다.

    조립식 매장 키트를 설명서대로 한 번에 세우는 단계

    # 서버
docker compose -f compose.prod.yaml up -d --build
docker compose -f compose.prod.yaml ps   # mysql·web·nginx 모두 running

  7. DB 준비하고 AI 검색 자료 넣기

    DB 표를 만들고(migrate), 관리자 계정을 만들고, PDF 5개를 잘게 나눠 ChromaDB에 넣었습니다(12조각).

    장부 양식을 만들고, 자료실에 매뉴얼을 꽂아 두는 단계

    # 서버 (manage.py = 컨테이너 안의 Django 명령)
manage.py migrate
manage.py createsuperuser
manage.py index_docs     # PDF 색인 완료: 12개 청크

  8. 접속해서 확인하기

    홈·게시판·로그인·AI 검색이 모두 정상(200)으로 열렸습니다. AI 검색에 "교환·반품은 며칠 안에?"라고 묻자 환불교환정책.pdf를 근거로 "단순 변심 7일 이내"라고 답했습니다.

    문을 열고 첫 손님을 받아 보는 단계

    등록되지 않은 주소로 들어오면 400으로 막히는 것도 확인했습니다(ALLOWED_HOSTS).

  9. 자동 배포 연결 (GitHub Actions)

    GitHub가 서버에 들어올 수 있게 열쇠를 맡겼습니다. 이제 코드를 push하면 GitHub가 알아서 서버에 접속해 새 코드로 다시 켜 줍니다.

    본사가 새 물건을 자동으로 배송·진열해 주도록 계약하는 단계

    GitHub Secret 이름넣은 값뜻
    EC2_SSH_KEYgha_key 개인키서버 문 열쇠
    EC2_HOST서버 IP어느 서버로 갈지
    EC2_USERubuntu누구로 들어갈지
     
    # push하면 Actions가 서버에서 대신 실행하는 명령
cd ~/app && git pull --ff-only
docker compose -f compose.prod.yaml up -d --build
manage.py migrate --noinput && manage.py collectstatic --noinput

스스로 점검

이해했는지 확인하는 질문

코드는 GitHub에 있는데 .env는 왜 서버에 따로 만들었나?

API 키와 DB 비밀번호가 들어 있어서 Public 저장소에 올리면 누구나 볼 수 있기 때문입니다.

주소로 들어갔는데 400 Bad Request가 난다면?

.env의 DJANGO_ALLOWED_HOSTS에 그 주소가 없는 것입니다. 추가한 뒤 컨테이너를 다시 만듭니다.

nginx는 왜 따로 두나? Django만 켜면 안 되나?

Django(gunicorn)는 기능 처리에 집중하고, 손님 응대와 그림·CSS 전달은 nginx가 더 빠르고 안전하게 합니다.

서버를 지운 뒤 push하면 어떻게 되나?

Actions가 접속할 서버가 없어 실패합니다. 다시 배포하면 새 IP로 EC2_HOST Secret만 바꾸면 됩니다.
